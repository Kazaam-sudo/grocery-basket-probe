# Prompt 03: static web MVP and GitHub Pages

Ты работаешь в репозитории `Kazaam-sudo/grocery-basket-probe`.

Цель задачи — подготовить демонстрационный рекомендательный web app, который
публикуется на GitHub Pages без backend и без обращения к сайтам ритейлеров из
браузера.

## Зафиксированные ограничения

- интерфейс только рекомендательный;
- не оформлять заказ, не принимать оплату и не переносить корзину;
- не использовать аккаунты, cookies, SMS, CAPTCHA bypass, закрытые токены или
  агрессивные прокси;
- не подключать live-источники в браузере;
- источник демо-данных — версионируемый JSON-снимок;
- публичный UI не должен собирать точный домашний адрес или персональные данные.

## Что должно быть в результате

1. Статическая страница с выбором тестовой зоны Москвы/МО.
2. Ввод до 20 товаров по одному в строке.
3. Сравнение subtotal в Пятёрочке, Магните и Ленте.
4. Покрытие корзины, упаковка, наличие, время снимка и предупреждение об
   неизвестных доставке/сборах.
5. Кнопка публичного перехода на сайт сети.
6. Копирование подготовленного списка и экспорт CSV.
7. Явная пометка, что данные демонстрационные и не создают заказ.
8. GitHub Actions workflow с `configure-pages`, `upload-pages-artifact` и
   `deploy-pages`.

## Критерии приёмки

- `web/index.html` открывается через простой статический сервер;
- обновление текста корзины не требует перезагрузки страницы;
- недоступный товар не считается нулевой стоимостью;
- одна неизвестная позиция не ломает расчёт остальных;
- ссылки на сайты ритейлеров открываются в новой вкладке;
- CSV содержит запрос, цену каждой сети и упаковку;
- workflow запускается только для изменений `web/**` или вручную;
- в коде нет ключей, токенов, cookies и сетевых запросов к сайтам магазинов;
- README и `docs/free-hosting.md` объясняют включение Pages и ограничения.

## Что не делать

- не добавлять React/Next/Vite только ради сборки;
- не добавлять серверный endpoint в Pages workflow;
- не называть демо-цены актуальными;
- не имитировать импорт корзины в приложение ритейлера;
- не подключать платежи, авторизацию или аналитику с персональными данными.

## Проверка

```bash
python3 -m http.server 8080 --directory web
```

Проверить вручную: загрузить пример, изменить список, выбрать другую тестовую
зону, сравнить три карточки, открыть сайт магазина, скопировать список и скачать
CSV.
