# Бесплатный web app: GitHub Pages + снимки данных

## Решение для первого публичного прототипа

Первый web app размещается как статический сайт:

```text
GitHub repository
        ↓ push в main
GitHub Actions
        ↓ upload-pages-artifact
GitHub Pages
        ↓
браузер пользователя → web/index.html + app.js + data/demo-quotes.json
```

Интерфейс не вызывает сайты магазинов из браузера. Он читает последний
версионируемый JSON-снимок. Это убирает CORS, не раскрывает секреты и не создаёт
нагрузку на каталоги при каждом пользовательском просмотре.

После появления разрешённого источника отдельный ограниченный ingestion-run может
обновлять JSON-снимок через GitHub Actions. До этого в приложении честно указано,
что данные демонстрационные.

## Почему FastAPI и PostgreSQL не размещаем на GitHub Pages

GitHub Pages публикует статические файлы. Он не запускает Python-процесс, очередь,
PostgreSQL или приватные секреты. Поэтому текущий Python-каркас остаётся будущим
API/ingestion-контуром, а Pages обслуживает только пользовательский интерфейс и
публичный снимок.

Для коммерческого SaaS GitHub Pages нельзя считать окончательным backend-хостингом:
в документации GitHub есть ограничения для сайтов, ориентированных на коммерческие
транзакции или SaaS. На этапе технического прототипа используется только
рекомендательный read-only сценарий без аккаунтов, оплаты и заказа.

## Как включить Pages в репозитории

1. Открыть `Settings` → `Pages`.
2. В поле `Source` выбрать `GitHub Actions`.
3. Смержить PR с web app в `main`.
4. Открыть URL из environment `github-pages` в последнем workflow run.

Ожидаемый адрес для этого репозитория:

```text
https://kazaam-sudo.github.io/grocery-basket-probe/
```

URL нельзя считать рабочим до успешного workflow run и проверки сценария в
приватном окне браузера.

## Запасной бесплатный вариант

Если позже понадобится serverless API, тот же каталог `web/` можно подключить к
Cloudflare Pages. Статические запросы там обслуживаются отдельно от Functions; API
потребует отдельного контроля бесплатной квоты. Это запасной вариант, а не часть
первого Pages-спринта.

## Ограничения текущего демо

- цены взяты из `web/data/demo-quotes.json`;
- точный адрес, доставка, персональные скидки и карта магазина не моделируются;
- кнопка магазина открывает публичный сайт, но не переносит корзину;
- живые коннекторы Пятёрочки, Магнита и Ленты пока не подключены;
- в снимке нет фотографий и длинных описаний товаров.

## Критерий перехода к API

Переходить от JSON-снимка к отдельному API стоит только когда подтверждены:

1. разрешённый источник хотя бы одной сети;
2. повторяемый сбор без CAPTCHA, SMS, закрытых токенов и блокировок;
3. измеримая свежесть цены и наличия;
4. необходимость динамического адреса, которую нельзя закрыть снимками;
5. понятная стоимость и ответственность за API-хостинг.
